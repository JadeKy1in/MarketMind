### 2.1 6-Phase 分析工作流 (扩展为 7-Phase)

**来源**：`docs/methodology/analysis-workflow.md`
**迁移状态**：直接使用，将 Phase 4 拆分为两个 Phase（收敛 + 对抗构建写作）

| Phase | 用途 | 出口条件数 |
|:--:|------|:--:|
| 0 | 知识审计 + Domain Priming | 5 (含新鲜度时间阈值) |
| 1 | 框架设计（禁止评分） | 4 |
| 2 | 数据收集（只收集不分析） | 5 |
| 3 | 发散分析：3 视角 + 3 假设 steelman | 5 |
| 4 | 收敛综合：假设处理 + 证据合成 | 6 |
| 5 | 对抗构建写作：大纲辩论 + 并行写作 | 6 |
| 6 | 深度红队攻击 + 事实核查 | 7 |
| 7 | 人工终审 + 最终整合 + 输出 | 5 |

### 2.2 [V]/[H]/[NV] 标注体系

**来源**：analysis-workflow.md Phase 0
**迁移状态**：直接使用，三标签不变

- `[V: 来源, 日期]` — 已验证，含可溯源出处和日期
- `[H: 推理逻辑]` — 假设，推理链已在正文中陈述
- `[NV]` — 需验证（Phase 0 收集，Phase 6 前全部解决或升级为风险）

### 2.3 RCR 规则 (拆分版)

**来源**：adversarial-construction.md 第二章
**迁移状态**：拆分为 RCR-Self 和 RCR-Cross 以适应并行/串行混合执行

**RCR-Self** (每个 Agent 独立执行，并行阶段适用):
1. **Reflect**：产出前先写"本产出最容易出错的地方是______"
2. 在 Agent prompt 中内嵌此要求，Agent 独立完成

**RCR-Cross** (Agent 之间交叉执行，在并行阶段之后追加串行轮):
1. **Critique**：攻击对方版本，引用具体段落/数字/逻辑链
2. **Refine**：修改附带新推理步骤，不能只写"采纳建议"
3. 每个多 Agent 并行阶段后追加一轮 RCR-Cross

### 2.4 Agent 派发协议（三道题测试 + 反模式）

**来源**：analysis-workflow.md

**三道题测试** (每次派发前):
1. **自主性**：我能用现有数据回答吗？能 → 不派发
2. **具体性**：问题是否窄到 Agent 能一次回答？不能 → 先拆分
3. **整合性**：输出将进入文档的哪个具体章节？不清楚 → 先理结构

**反模式** (红色警报——停下反思):
1. 你把用户用来举例的东西当成了研究对象 → 例：用户随口提"味知香"，你就只分析味知香
2. 你在派 Agent 验证自己已有的假设 → 循环确认
3. 你没有指定整合目标 → 会导致追加行为
4. 你在被用户质疑一个方向后派 Agent → 你在转移，不是分析

### 2.5 二进制 Phase 门控

每个 Phase 出口条件是二进制的：**全部为 TRUE 才能进入下一 Phase**。

### 2.6 单一文档规则 (完整纪律)

**来源**：analysis-workflow.md 第170-186行

执行规则:
1. 新信息适合已有章节 → 立即整合进去
2. 需要新章节 → 按逻辑位置添加，**不是**在末尾
3. 挑战当前结构 → **先重构文档**再添加内容

红色警报:
- 创建"补充"或"附注"章节
- 把发现添加到文档末尾
- 使用"如前文补充所述"措辞
- 同一主题在两个不同位置讨论

作用范围：Phase 0 起全程（非仅 Phase 4-6）

## 三、需适配迁移的要素

### 3.1 多 Agent 并行分析（替代 Shadow 生态）

**维度-视角映射表** (Phase 1 六维 → Phase 3 三视角):

| Phase 1 分析维度 | 分配给 | 说明 |
|------|:--:|------|
| 市场 (规模、增速、结构) | Agent A (需求) + Agent B (供给) | 两个视角共享基础数据 |
| 消费 (行为、偏好、价格弹性) | Agent A (需求) | 需求侧专属 |
| 竞争 (格局、CR5、进入壁垒) | Agent B (供给) | 供给侧专属 |
| 供应链 (上游、中游、冷链) | Agent B (供给) | 供给侧专属 |
| 技术 (工艺、保鲜、智能化) | Agent B (供给) | 供给侧专属 |
| 政策 (监管、标准、补贴) | Agent C (政策/宏观) | 政策侧专属 |

**Agent 配置**:
```
Agent A（需求视角）：消费者行为、市场规模/增速/结构、渗透率、价格弹性
Agent B（供给视角）：产业链、产能、成本结构、技术壁垒、竞争格局
Agent C（政策/宏观视角）：监管政策、食品安全、冷链基建、区域差异、宏观经济
```

**[RCR-Cross]** Phase 3 完成后，3 个 Agent 交叉审阅彼此产出并互相 Refine。

### 3.2 对抗构建法 5-Phase（适配版）

| Phase | 原 Agent 配置 | 调整后配置 | 执行位置 |
|:--:|------|------|:--:|
| 1. 大纲辩论 | P(激进) vs O(稳健) vs J(裁判) | P=看多，O=看空/谨慎，J=裁判 | 框架 Phase 5.1 |
| 2. 并行写作 | W1(行动导向) + W2(叙事导向) + C(对比) | W1=数据驱动分析型，W2=故事驱动可读型 | 框架 Phase 5.2 |
| 3. 红队攻击 | R1+R2+R3 | R2 改为"行业逻辑可操作性" | 框架 Phase 6 |
| 4. 事实核查 | F(逐项比对) | 使用贵模型 (多源比对需要语义推理) | 框架 Phase 6.4 |
| 5. 人工合成 | 人类作者 | 合并到【用户确认点 #4】 | 框架 Phase 6→7 之间 |

### 3.3 Flash/Pro 模型路由

| 任务类型 | 使用模型 | 说明 |
|------|:--:|------|
| Web 搜索、数据提取、初筛分类 | 便宜模型 | 大量并行搜索 |
| 深度分析、对抗性推理、报告写作 | 贵模型 | 需要深度推理能力 |
| 红队攻击 | 贵模型 | 需要发现隐藏的逻辑漏洞 |
| 事实核查 | **贵模型** | 多源比对需要语义推理和语境判断——修正 v1.0 的"便宜模型"错误 |

### 3.4 Resonance/Fragility → 报告质量反馈循环

- **Resonance** → **论点支撑度评估**：每个核心论点是否有 ≥2 条独立证据线（对应 analysis-workflow.md Phase 4.3，此处前置为主动检查）
- **Fragility Scanner** → **最弱论点识别**：找出证据最薄弱的 3 个论点，针对性加固
- 两者整合为 Phase 4 出口条件的一部分

### 3.5 能力规则 (Capability Rule) 的市场调研适配

**来源**：analysis-workflow.md 第188-191行
**迁移状态**：从"技术能力是常量"转换为"结构性能力是常量"

市场调研中的能力规则：
- **结构性能力 (常量)**：消费能力上限、供应链弹性上限、政策空间边界、人口结构趋势
- **当前状态 (变量)**：当前渗透率、当前 CR5、当前政策版本、当前融资热度

当分析"X 市场是否会增长到 Y 规模？"时，转换为：
- "当前消费渗透率是 Z%"(变量)，但"消费能力上限是 W 元/人/年"(常量)
- 结论必须区分：什么是结构性天花板，什么是当前状态

作为 Phase 4 出口条件 4.3 的子条件。

## 四、需要从零构建的要素

### 4.1 行业研究数据源配置 + Data Gap Protocol

**数据源**：国家统计局、商务部、农业部、各省统计年鉴、艾媒咨询、中商产业研究院、智研咨询、Euromonitor、天眼查/企查查、社交媒体舆情、日本预制菜对标数据

**来源可信度分级**:
| 级别 | 来源类型 | 示例 |
|:--:|------|------|
| A | 政府统计/行业协会白皮书 | 国家统计局、中国烹饪协会 |
| B | 券商研报/知名咨询机构 | Euromonitor、艾媒咨询 |
| C | 企业财报/招股书 | 味知香年报、安井食品招股书 |
| D | 新闻媒体/企业 PR | 行业媒体报道 |
| E | 自媒体/非官方渠道 | 需交叉验证方可使用 |

**Data Gap Protocol** (4-step fallback，每个维度搜不到数据时触发):
1. **Step 1**: 尝试 3 个替代搜索词
2. **Step 2**: 如果仍为空，尝试相邻维度的数据外推
3. **Step 3**: 如果仍不可得，标记为 `[NV: 公开数据不可得]`，使用最接近的替代指标 + 明确假设 `[H]`
4. **Step 4**: 记录此 gap 对结论可靠性的影响

### 4.2 市场规模估算模型

- 自上而下法（宏观消费支出 × 渗透率）
- 自下而上法（企业出货量 × 均价 × 品类数）
- 日中日对标法（日本人均消费 × 中国人口 × 渗透率调整系数）

### 4.3 行业生命周期阶段判定

判定维度：市场增速 vs GDP 增速、渗透率变化速度、新进入者 vs 退出者、CR5 趋势、融资热度

### 4.4 框架自我学习与知识积累 (EMA + Crystallization)

**来源**：MarketMind CLAUDE.md 第167行 (EMA) + Phase 2 Shadow Crystallization

**EMA 低 alpha 学习 (0.1-0.2)**:
- 单一纠正只微调行为，不翻转
- 3+ 跨上下文的持续信号 → 提升为规则
- 单一纠正 7 天半衰期衰减
- 应用场景：红队发现权重、用户纠正、数据源可信度调整

**Crystallization 知识库**:
- 每次报告完成后，Facts with ≥2 independent `[V]` sources → crystalized
- 下次同行业报告 Phase 0 优先加载 crystalized facts
- Crystalized facts 仍需 freshness check (过期自动降级为 `[NV]`)
- 存储位置：`projects/marketmind/.claude/calibration/` 和项目级知识库

**度量指标** (每次报告后记录):
1. 红队有效发现率 (被采纳的挑战 / 总挑战数)
2. Phase 回退率 (因门控失败回退的次数 / 总 Phase 数)
3. 数据覆盖率 (有 ≥1 条数据的维度 / 总维度数)
4. [NV] 解决率 (Phase 6 前解决的 [NV] / Phase 0 建立的 [NV] 总数)
5. Token 实际消耗 vs 预算

### Agent 编排机制

**真正并行** (Agent 之间无依赖，可同时启动):
- Phase 3.1: 3 Perspective Agent (共享 Phase 2 数据，独立分析)
- Phase 5.1: P + O 大纲辩论 (共享 Phase 4 收敛结论)
- Phase 5.3: W1 + W2 并行写作 (共享 J 的合并大纲)
- Phase 6.1-6.4: R1 + R2 + R3 + F (共享 Phase 5 初稿)

**伪并行** (内部有串行依赖):
- Phase 5.2: J 必须等 P 和 O 完成
- Phase 5.4: C 必须等 W1 和 W2 完成

**RCR-Cross 追加轮**:
- Phase 3.2: 3 Agent 交叉 Critique + Refine (在并行产出后)
- Phase 5: J 的 Critique → C 的 Critique → Refine (内嵌在流程中)

## 六、差异、风险与缓解

### 6.1 不可迁移的能力

| MarketMind 能力 | 原因 | 影响 |
|------|------|------|
| 实时金融数据流 | 依赖 Finnhub API | 无影响 |
| 虚拟持仓 + 排名竞争 | 投资分析特化 | 无影响 |
| Shadow 7天隔离期 | 金融合规 | 简化——报告场景可缩短周期 |
| 事后验证 (post-hoc) | 市场预测可验证，报告结论验证周期长 | **已缓解**: Crystalized facts 跨报告一致性检查替代 |

### 6.2 新增风险

1. **搜索质量依赖**: 缓解——多源交叉验证 + Data Gap Protocol + 来源可信度分级
2. **Agent 领域知识盲区**: 缓解——Phase 0 Domain Priming (术语表 + 产业链 + 企业清单)
3. **中国数据可得性**: 缓解——Data Gap Protocol + `[NV]` 标注 + `[H]` 推理
4. **对抗构建法"单一源文档"前提不成立**: 缓解——Phase 2 产出格式化为"综合数据源文档"作为 surrogate source
5. **Agent 可能使用过时框架**: 缓解——prompt 明确"以 Phase 2 收集数据为唯一事实来源"

## 七、成功标准

1. **流程合规**：7 Phase 全部通过门控，5 个用户确认点完成
2. **事实标注**：100% 事实性陈述携带 `[V]`/`[H]`/`[NV]`
3. **红队覆盖**：≥ 7 次红队门控 + 4 Agent 深度攻击，≥ 15 条有效挑战
4. **多视角**：3 个独立视角交叉验证，分析性结论重叠 < 30%
5. **数据溯源**：≥ 20 条独立数据来源，含日期和 URL，覆盖 A-C 级来源
6. **可执行建议**：≥ 3 层级 (战略/运营/投资)，每条附带证据引用
7. **能力-状态区分**：核心结论明确区分结构性能力和当前状态
8. **可复现 (长期)**：核心主张可在另一组 Agent 执行时复现 (≥ 80% 一致性)
9. **输出完整**：MD + HTML 双格式，参考列表完整
10. **决策可审计**：关键自主决策附带 confidence 标注，记录到执行日志
