# 每日汇报与汇报员

> 所有人要求（2026-09-28）：主流程每天向所有人汇报当天收到的信息和投资决策，之后可以基于这些信息交流；汇报推送到微信并放在仪表盘。

## 每日汇报（`marketmind/reports/daily.py`）

- **时间**：工作日自动运行的最后一步（警报之后），约纽约 09:00 前完成。
- **内容**：代码先从当天的文件和账本收集事实——新闻要闻（抓取时保存的前 40 条标题，`data/news/<日期>.json`）、证据层、主管线决策（交易卡 / 不交易、纸面交易、红队质疑、脆弱性）、影子与临时影子动向、事件影子、持仓巡检、大行情警报、晋升阶段；再由 1 次主管线级别的模型调用写成中文汇报（今日要闻、证据层、主管线决策、影子动向、实盘持仓、大行情警报、值得关注）。提示词要求只用给定事实，不补数字、不给交易指令。
- **模型不可用时**：照样生成一份"原始事实"版，不会没有汇报。
- **去向**：`data/reports/<日期>.json`；仪表盘"今日简报"页顶部；微信（Server酱，超过 4,000 字截断并附仪表盘链接）。
- **推送失败**：遇到网络错误（超时、断连）或 HTTP 5xx，每个渠道自动重试 2 次（间隔 2 秒、8 秒），4xx 不重试。超时后重试可能导致同一条消息收到两次。所有渠道都失败时，汇报写入补发队列 `data/scheduler/push_queue.json`，下一次计划任务触发（`scheduled_run.py`）或 watchdog 运行时补发，队列保留 3 天。2026-10-02 曾因 Server酱 一次超时丢失当天汇报。
- 周末不生成（周末只跑结算和加密影子）。

## 汇报员（仪表盘"汇报员"页）

- 只读问答：能看到最新的今日汇报、账本、简报、影子成绩、证据层、持仓、警报；提到记录时引用编号，代码核对编号真实存在。
- 适合问："今天为什么不交易？""影子做多 SPY 的理由是什么？""NVDA 为什么建议换仓？"
- 终端里的 `python marketmind/app.py --mode interactive` 仍可与 L1 做苏格拉底式讨论。
