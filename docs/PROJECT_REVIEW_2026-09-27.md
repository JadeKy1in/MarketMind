## 1. 项目真实意图（综合全部文档后的一句话）

> 一个**人机协作的 AI 投研工作站**：每天用多源信息做分层分析，给出"交易 / 不交易"的建议，由人手动在 Robinhood 下单。与此并行运行一个由**虚拟基金经理（影子）**组成的竞技场：影子每天被迫做虚拟决策、互相竞争、淘汰和进化，优秀者毕业成为顾问。**Playground** 把外部高手的思维框架蒸馏成候选 Agent，经过验证后接入。整个系统通过复盘不断积累经验，并借助权威一手数据刺破市场叙事。

**所有人的投资目标（2026-09-27 口述）**：
- 一年中大部分时间持币观望，抓住 3-4 波大行情，只吃中间一段，不冒进，不被套；
- 本金约 3 万美元；
- 可以承受较大回撤，但不能是期权那种归零式的回撤，不碰期权；
- 要投加密货币；
- 所有标的都用来训练影子，实盘只投较稳妥的标的；
- 前期以模拟为主，后期上真钱。

## 6. 晋升与淘汰机制：评价与优化

**设计中合理、应当保留的部分**
- 多指标复合排名，单一指标权重不超过 40%，防止被操纵。
- 按样本量和竞争者数量做贝叶斯剪发。
- 等级（相对排名）和毕业（绝对门槛）分开。
- 无任期原则：今天触发降级条件，今天就暂停。
- 秘密挑战者 + 配对检验。
- 毕业前的压力测试。
- 纸面与实盘落差的折扣。
- Min-bet（$100）交易占比超过 60% 时降权（final-plan:744）：这条恰好能奖励"知道自己不知道"。

**根本问题**
1. **没有成绩来源**：虚拟交易 0 笔、打分 0 条，整个机制在空转（C03、第 4 节）。
2. **门槛太多套，而且太松**：Tier1 只要 5 笔交易，统计上分不清本事和运气。
3. **没有做多重比较校正**：24 个影子，加上 Playground，再加上挑战者，候选越多，靠运气冒出来的"冠军"就越多。
4. **没有零技能对照**：专家影子没有和"同领域随机选"或者"领域 ETF"比较。
5. **机制过早复杂化**：配额、紧急配额、育种、繁殖都建立在不存在的数据上。

**优化后的统一晋升阶梯（建议）**

```
Playground 候选 / 新影子 / Beta
   │  条件：manifest 合规 + 信息防火墙 + 每日强制决策（确信度 + 可证伪条件）
   ▼
见习（Probation）：进入竞技场，所有预测进入统一账本
   │  最低样本：≥60 个交易日，且有效独立样本 ≥ 最短样本期（MinTRL，考虑持有期重叠）
   │  必须跑赢：同领域随机选 + 领域 ETF + 主 AI 基准（扣除成本后）
   │  统计：真正的 CSCV/PBO（T×N 矩阵）+ 按"历史全部试验数"校正的 DSR + Brier/校准
   ▼
正式影子（Ranked）：参与复合排名；等级只影响展示，数据不足前不影响配额
   │  毕业：Tier1/Tier2 + 压力测试 + 一段前向样本外期（不与任何调参期重叠）
   ▼
顾问（Advisor）：意见进入"大行情警报"的共识判断（不投票，不自动决策）
   │  持续监控：CUSUM/BOCPD 发现衰退 → 当天暂停（启用现有孤儿代码）
   ▼
淘汰：连续垫底 → 挑战者对比（用账本成绩）→ 替换 / 恢复
```

### 7.3 标的两层结构

| 层 | 范围 | 用途 | 打分方式 |
|---|---|---|---|
| **可交易层** | Robinhood 全部品类：股票、ETF、期权、期货、加密货币、事件合约 | 影子的虚拟交易、主管线建议、所有人实盘 | 按真实成交价结算（期权、期货按合约规则） |
| **关联层** | Robinhood 没有、但会传导过来的资产：A 股 / 港股、日债与日元套利、欧洲利率、农产品现货、利率期货、航运、私募信贷等 | 关联分析师研究"传导链"，结论落到可交易层的代理标的（例如中国刺激 → 铜 / FXI / 钢铁股） | 对关联资产本身的方向做预测并打分，同时对它推导出的代理标的预测打分 |

**提案**：新增 **"跨市场传导"类影子**，例如中国 / 亚洲、日本与全球套利、欧洲。它们的职责是跟踪不可交易的驱动因素，然后把结论翻译成可交易的标的。

### 7.4 白箱要求（交互设计的硬约束）

警报驱动不等于黑箱。仪表盘必须随时能查看以下内容，并且每一项都能点进去看原始理由：

1. 今日简报；
2. **统一账本**：每一条预测、确信度、可证伪条件、结算结果；
3. **影子竞技场**：每个影子的虚拟持仓、理由、成绩曲线，以及等级变化的原因；
4. **证据层**：叙事与数据的背离清单，附一手来源链接；
5. 主管线的推理链：每一层的输入、输出、红队意见；
6. 晋升 / 淘汰日志；
7. 系统健康：数据源状态、成本、错误、告警。

**对话式汇报（所有人 2026-09-27 提出，评审者提案，待确认）**：设两个角色，二者读取同一份事实底座（统一账本 + 运行日志）。

| 角色 | 形态 | 职责 | 硬规则 |
|---|---|---|---|
| **汇报员**（嵌入工具） | 在现有 `api/chat_handler.py`（DeepSeek）的基础上改造，仪表盘里随时可以对话 | 日常问答：系统状态、影子表现、警报原因、证据来源 | ① **只读**：不能修改状态，不能替人做决定 ② 每个回答都要**引用账本或日志的记录编号** ③ 没有数据就明说，成绩差就直说（Law 7 的延伸） |
| **审计员**（外部，Claude Code） | 定期（每周或每月）由所有人发起的会话 | 独立审计：数据完整性、晋升统计是否可靠、代码健康、**抽查汇报员的发言是否与数据一致** | 与被审计系统使用不同的模型，不参与日常分析 |

之所以设两层，是因为嵌入的 AI 在"自己汇报自己"，存在替系统结论圆场的风险，需要一个它影响不了的外部核查。这与"红队质疑主分析""影子必须跑赢基准"是同一个原则。
