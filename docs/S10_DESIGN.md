# S10 设计：冷门数据发现链（数据先行 → 是否已反映 → 等待确认 → 可归因）

> 规格来源：`docs/SPEC_v3.md` §1（打破信息茧房的投研工作站）、§4 ①②③、§5、§7。日期：2026-09-28。状态：已确认（所有人 2026-09-28）。

## 目标

系统的核心用途是：用官方但冷门的数据，通过启发式挖掘发现并验证机会；再回到市场，判断机会是否已被价格反映（price in），以及是否需要等待确认信号。现有流程缺四环，本阶段补齐：

1. **数据先行异常扫描**：现有证据层从新闻出发（新闻说法 → 一手数据核对），仍在新闻的视野之内。新增从数据出发的扫描：冷门官方序列相对自身历史出现异常，而新闻报道很少。
2. **代码计算"是否已反映"**：现在只有 L1 由 LLM 填一个 0–1 的 `price_in_score`，违反"数字由代码产生"（SPEC §2 L3）。改为代码计算。
3. **观察名单与确认触发**：决策只输出"入场"卡，判为"等待"的标的被丢弃。新增带确认条件的观察项，条件满足时推送并入账。
4. **账本记录数据来源**：每条预测写明是哪条数据、哪个异常引出的，以便日后按数据源统计有效性。

## Scope Anchor

- goal：上述四环在每日运行中产出、进入账本、在仪表盘和每日汇报中可见。
- in_scope：新模块 `marketmind/discovery/`（异常扫描、已反映度）、`marketmind/watchlist/`（观察名单）；账本 `meta.origin` 字段；主管线决策 prompt 的"等待"输出；每日汇报与仪表盘的展示；离线测试。
- out_of_scope：付费数据源；新增需要密钥的数据源；自动下单；S9 自进化；修改晋升阶梯口径（另议）；把背离清单喂给主管线（所有人 2026-09-28 决定暂缓）。
- expand_requires：所有人在对话里确认。

## 1. 数据先行异常扫描（`marketmind/discovery/anomaly.py`）

**序列注册表**：每条冷门序列一个条目：`id`、取数函数（返回 `[(date, value)]`，至少 1 年历史）、发布频率、单位、关联可交易代理（例如 JGB 10Y → FXY、EWJ、TLT；OKX 资金费率 → BTC-USD；FINRA 卖空占比 → 该股票）、新闻关键词。首批只用已接入且免密钥或已有密钥的来源：

| 来源 | 序列 |
|---|---|
| FRED（已有密钥） | 准备金、TGA、ON RRP、SOFR−IORB、HY/BBB/CCC 利差、STLFSI、广义美元指数 |
| 纽约联储 | SOMA 各类持仓、常备回购用量 |
| 财政部 FiscalData | 各期限拍卖认购倍数、尾差 |
| 日本财务省 / ECB | JGB 2/10/30Y、欧元兑主要货币 |
| Cboe | VIX 期限结构（VIX9D/VIX、VIX/VIX3M）、SKEW |
| OKX / DefiLlama | 资金费率、未平仓量、稳定币总供应 |
| FINRA RegSHO / Finnhub | 个股卖空成交占比、内部人净买卖（仅观察清单内个股） |
| EIA（已有密钥） | 原油 / 成品油库存 |

**异常判定（纯代码）**：对每条序列取最新值与最近变化（按频率：日频 5 日、周频 4 周、月频 3 个月），计算
- 相对过去 1 年同口径变化的 z 分数与分位；
- 水平值的 1 年分位；
- 是否创 1 年新高 / 新低。

满足任一条即为异常：|z| ≥ 2、分位 ≤ 5% 或 ≥ 95%、创 1 年新高 / 新低。阈值写在配置里，所有异常都记录原始数值，不做主观解读。

**新闻覆盖度（反茧房指标）**：用当天及过去 7 天已抓取的新闻标题和摘要，按序列关键词计数。覆盖度 = 命中篇数。覆盖度 ≤ 2 的异常标为"冷门异常"，排在前面。

**输出**：`data/discovery/<日期>.json`，每条异常含：序列、最新值、变化、z、分位、覆盖度、关联代理标的、数据发布日期（用于第 2 节）。

## 2. 已反映度（`marketmind/discovery/priced_in.py`，纯代码）

对每个"异常 × 关联代理标的"组合，从**数据发布日**起计算：

| 指标 | 算法 |
|---|---|
| 已走幅度 | 代理标的自发布日收盘至今的收益，除以 ATR14 换算为 ATR 倍数；股票另算相对所属行业 ETF 的超额 |
| 方向一致 | 已走方向是否与异常隐含方向一致（隐含方向由注册表为每条序列预设，例如"准备金大降 → 流动性收紧 → 风险资产偏空"，仅作初始假设，由账本检验） |
| 成交量 | 发布日以来平均成交量相对前 20 日均值的倍数 |
| 拥挤度 | 有数据时附上：资金费率分位（加密）、卖空占比变化（个股） |

分档：方向一致且已走 ≥ 2 ATR → **已反映**；方向一致且 0.5–2 ATR → **部分反映**；< 0.5 ATR 或方向相反 → **未反映**。分档阈值写在配置里，日后按账本校准。

L1 的 `price_in_score`（LLM 估计）保留在叙事中作为文字参考，但不再进入决策输入；决策输入改为本节代码结果。

## 3. 观察名单与确认触发（`marketmind/watchlist/`）

**来源**：
- 主管线决策：prompt 新增 `watch_cards`，用于"方向看对但需要等待"的标的。每张卡必须给出一个或多个**代码可检验**的确认条件，只允许以下类型：收盘价上破 / 下破某价、收盘站上 / 跌破某均线（20/50/200 日）、成交量 ≥ N 倍 20 日均量、某日期之后（等数据公布）。价位由 L3 代码给出，LLM 只能从中选择。
- 异常扫描中"未反映"或"部分反映"的冷门异常，自动生成观察项，确认条件默认为"代理标的收盘突破 20 日高点（偏多）或跌破 20 日低点（偏空）"。

**生命周期**：`watching` → `triggered`（条件满足，写入账本，次日开盘入场）/ `expired`（默认 20 个交易日未触发）/ `invalidated`（反向条件满足）。每天在工作日运行和周末运行（加密）中检查。

**推送**（所有人 2026-09-28 决定）：主管线观察卡触发时推送微信；异常扫描自动生成的观察项只写进每日汇报和仪表盘，不推送。

**"等待"本身也要结算**：每个观察项创建时同时记一笔"立即入场"的对照记录（`source_type=watch_counterfactual`），到期与触发入场的那笔比较，衡量"等待"这一判断是否值钱。

## 4. 账本来源归因

`LedgerEntry.meta` 新增 `origin`（不改表结构，`meta` 已是 JSON）：

```json
{"origin": {"kind": "anomaly|evidence|news|watch|scanner|shadow",
            "series": ["fred:WRESBAL"], "anomaly_id": "2026-09-28:fred:WRESBAL",
            "priced_in": "partial", "coverage": 1}}
```

主管线卡片的 `origin` 由卡片所引用的输入推出：候选若来自异常扫描，带上异常 id；影子记录标 `shadow` 与其上下文中出现的数据段标题。仪表盘新增"按数据来源"成绩表：条数、已结算、平均净收益、胜率、Brier。

## 5. 接入每日流程

- 工作日运行：新闻采集后并行跑异常扫描（纯代码 + 取数，不花 token）→ 已反映度 → 结果作为 L2 候选的一个来源，同时写入决策输入 → 决策产出交易卡 / 观察卡 / 不交易卡 → 观察名单检查 → 账本。
- 周末运行：只扫描加密相关序列并检查加密观察项。
- 每日汇报新增两段："冷门异常（覆盖度低）"与"观察名单变化（新增 / 触发 / 到期）"。

## 验收

1. 离线测试覆盖：异常判定、覆盖度、已反映分档、观察项生命周期、`origin` 写入；全量测试通过。
2. 一次真实运行：`data/discovery/<日期>.json` 有内容，每条异常都有原始数值与来源；数据不可用的序列明确列出，不静默跳过。
3. 至少一条观察项进入 `watching`，账本中对照记录存在；主管线卡片带 `origin`。
4. 每日汇报与仪表盘显示上述两段。

## 所有人决定（2026-09-28）

- 异常扫描结果**直接进入主管线**：作为 L2 候选来源之一，并进入决策输入；账本按来源归因，事后检验。
- 推送：只推主管线观察卡的触发（见第 3 节）。

## 风险

- 异常的"隐含方向"是预设假设，可能错；由账本按序列统计纠正，不作为结论展示。
- 新闻覆盖度只统计本系统抓到的新闻，不代表全网覆盖，属于近似指标。
- 部分序列历史不足 1 年（例如只保留 3 年的 FRED ICE 数据足够；个别新接入源可能不足），不足时只报水平值，不算 z 分数。
