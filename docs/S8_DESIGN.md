# S8 设计（第一部分）：大行情警报框架

> 规格来源：`docs/SPEC_v3.md` §1、§6.3、§10、§13（S8：Playground 接回 + 顾问 + 大行情警报）。日期：2026-09-28。

## 范围

- **做**：警报三条件的代码判定；观察模式（S7 之前）；警报记录进账本；所有人对警报的回应（接受 / 拒绝）与"放弃的价值"；推送层（与渠道无关，支持在中国可用的微信 / 企业微信 / 飞书推送）；仪表盘"警报"页。
- **不做**：顾问评选（S7，晋升评审）；Playground 接回；自动下单（L1/L2 禁止）。
- 所有人决定（2026-09-28）：S7 之前用**观察模式**；推送渠道要在中国能用（所有人以后回国，倾向微信）。

## 三个条件（SPEC §10，全部满足才发出）

| 条件 | 判定（纯代码） |
|---|---|
| A 顾问一致 | 近 5 天内，对同一标的做多的"顾问"至少 3 个，来自至少 2 个不同的组（基本面 / 动量 / 逆向 …）；同期做空该标的的顾问数不超过做多数的一半 |
| B 证据背离 | 近 5 天证据层有一条背离记录，押的方向与 A 相同，标的相同（宏观类用代理标的，如 TLT、BTC-USD） |
| C 趋势确认 | L3 三灯全绿（站上 200 周均线、日线结构完好、离关键阻力 > 3%） |

- **只列所有人能执行的工具**：Robinhood 可交易、非期权。v1 只发做多警报（所有人的目标是抓大行情的中段；看空时的风险提示由 S6 持仓巡检负责）。
- **顾问**：S7 之前没有毕业影子，用**全部在册上线的影子**代替，警报状态记为"观察"，**不推送手机**，只进账本和仪表盘，用来提前检验警报逻辑。S7 产生顾问名单后，只有顾问计入 A，警报状态为"正式"，才推送。
- 同一标的 10 个交易日内不重复发出。
- 满足 2 条的标的列为"接近触发"，只在仪表盘显示，不进账本。

## 账本

- 每条警报（观察或正式）记一条：`source_type=alert`，`source_id=alert:observe` 或 `alert:live`；做多，下一个开盘价入场，持有 20 个交易日，仓位 $1,000（观察用固定名义金额），确信度 0.6，可证伪条件 = L3 止损价（收盘跌破即判错），`meta` 里存三条条件各自的依据和记录编号。
- 所有人回应：`python -m marketmind.alerts ack <警报编号> accept|reject [--note ...]`，写入 `data/alerts/responses.jsonl`。被拒绝的警报就是 SPEC §6.3 的 missed_path：它的账本记录照常结算，仪表盘把"拒绝后的结果"单列出来，量化"放弃"的价值。

## 推送（`marketmind/alerts/notify.py`）

- 渠道由环境变量决定，设了哪个就用哪个（可以同时设多个）：Server酱（推到微信）、PushPlus（推到微信）、企业微信群机器人、飞书自定义机器人。具体接口格式见代码注释里的文档链接与核对日期。
- 密钥只从环境变量读，放在 URL 里的也不写日志；发送失败只记录渠道名和 HTTP 状态。
- `python -m marketmind.alerts test-notify` 发一条测试消息，确认渠道可用。
- 推送内容：标的、方向、三条依据的摘要、L3 入场区间 / 止损 / 目标、账本编号，以及"系统不下单，由你决定"。

## 运行

- 每日运行最后阶段（影子交卷、持仓巡检之后）执行；也可 `python -m marketmind.alerts run`。
- 报告写 `data/alerts/<日期>.json`（触发的、接近触发的、各条件统计）；仪表盘"警报"页读取。

## 实现说明（2026-09-29，红队修复）

- **观察模式持续到顾问能满足条件 A 为止**（`alerts/runner.py::load_advisors`、`can_satisfy_a`）：原实现只要 `data/advisors.json` 里有 1 个顾问就切到正式模式、只让顾问投票，而条件 A 需要至少 3 个顾问、来自至少 2 个组，于是在凑齐 3 个跨组顾问之前警报完全沉默。现在顾问人数 ≥ `MIN_ADVISORS` 且组数 ≥ `MIN_GROUPS` 才转为正式模式（只有顾问投票、推送手机）；否则继续用全部在册影子做观察模式（不推送），日志说明原因。
- 发现但未修改（超出本次范围）：`load_advisors` 只从长期名册取组别，`advisor_votes` 也只统计 `source_type = shadow` 的记录，所以晋升为顾问的 Playground 候选（`playground:` 编号，晋升评审里组别为 `playground`）既不计入模式判断，也不参与投票。是否让它们作为一个组参与条件 A，需要所有人决定。

## 验收

- 离线测试：三条件各自的边界（人数、组数、反对票、窗口）、不可执行工具被排除、观察模式不推送、10 天去重、账本记录字段、回应记录、推送各渠道的请求格式与失败处理（模拟 HTTP）。
- 用真实账本跑一次（观察模式），报告与仪表盘可见。
