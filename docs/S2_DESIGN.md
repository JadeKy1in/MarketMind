# S2 设计：标的全集 + 行情快照 + 统一账本与结算

> 依据：`SPEC_v3.md` §3、§4、§7、§13（S2 验收：任意一条预测都能自动结算）。日期：2026-09-27。

## 1. 范围

| 纳入 | 不纳入（后续阶段） |
|---|---|
| 可交易层标的全集：美股 / ETF（NASDAQ Trader 代码表）、加密货币（维护清单）、期货与事件合约（维护清单，仅登记） | 期权、期货、事件合约的**结算**（需要合约规则，S3 之后） |
| 行情数据源接口 + yfinance 实现；按时点保存的报价快照 | Alpaca 实现（所有人注册后接入） |

| 主管线的交易卡与被迫纸面交易写入账本；每日运行前自动结算到期记录；`--mode settle` | 旧存储（learning_store、calibration JSON 等）的迁移与下线 |

## 2. 标的全集（`marketmind/universe/`）

- 美股 / ETF：下载 `nasdaqlisted.txt`、`otherlisted.txt`，剔除测试代码，符号统一成 yfinance 写法（`BRK.B` → `BRK-B`）。缓存到 `data/universe/`，超过 7 天再刷新；下载失败时用缓存，并在日志里注明缓存日期。
- 加密货币：Robinhood 加密 API 的交易对接口需要密钥，暂用维护清单（注明来源与核对日期），拿到密钥后改为 API 同步。
- 期货、事件合约：维护清单，只用于判断"可交易"，暂不结算。
- 加密货币清单来源：Robinhood 官方页面 coin-availability（2026-09-27 核对，89 个可交易）；期货 52 个品种来自 Robinhood futures 页面。详见 `marketmind/universe/registry.py`。
- 优先股、权证、单位、配股权等代码不纳入（yfinance 写法不统一，也不是交易卡标的）。
- 接口：`is_tradable(ticker)`、`classify(ticker)` → 层级（tradable / linkage / unknown）+ 品类。`decision_guard` 的临时判断改为调用它；全集不可用时退回原来的后缀规则并记录日志。

## 3. 行情与快照（`marketmind/ledger/prices.py`）

- `PriceSource` 协议：`daily_bars(ticker, start, end)`；默认实现用 yfinance（经 `gateway/price_history`）。
- 快照：每次写入账本时，对涉及的标的记录一份报价快照（价格、数据源、数据日期），账本记录带 `snapshot_id`，事后能还原"当时看到的价格"。
- 结算用到的日线**不另存**：yfinance 返回的是复权价，不同日期抓取的复权基准不同，混存会出错。每条已结算记录保存自己的入场 / 离场日期、价格和数据源，足以追溯。
- 结算每次都从日线重新推演未结算记录（幂等），已结算记录不再改动。

## 4. 账本（`marketmind/ledger/`，`data/ledger.db`）

每条记录（SPEC §7）：编号、来源类型（main / main_forced / shadow / temp_shadow / playground / benchmark / owner）与来源编号、创建时间、快照编号、标的、层级、品类、方向（long / short）、入场规则、持有期、确信度、虚拟仓位（美元）、止损、目标、可证伪条件（文字 + 可选的机器规则）、理由摘要。

### 结算规则（全部由代码计算）

1. **入场**：
   - `next_open`（默认）：创建之后第一根日线的开盘价成交。
   - `zone`（交易卡）：从创建之后的第一根日线开始，价格进入入场区间（最低价 ≤ 区间上沿）即成交，成交价 = min(开盘价, 区间上沿)；创建后 5 根日线内（持有期更短时按持有期）没进入区间 → 作废（`void`，原因"未成交"），不计盈亏（所有人决定 2026-09-27：不追价，错过即放弃）。
   - 在开盘价成交、而开盘价已经越过**目标**（跳空）→ 作废（`void`，原因 `gap_target`），不计盈亏和 Brier（所有人决定 2026-09-29：卡片在入场前已失效）。
   - 在开盘价成交、而开盘价已经越过**止损**（跳空）→ 不作废，按止损离场并计入亏损（所有人决定 2026-09-29 第二次修订）：入场日 = 离场日 = 该 K 线日期，成交价记为**决策时的快照价**（按复权系数换算到当前序列；没有快照价时退回止损价），离场价 = 开盘价，毛收益 = 方向 × (开盘价 ÷ 快照价 − 1)，即从做出判断到开盘这段已经发生的全部不利变动，照常扣双边成本、计 Brier，离场原因 `stop`，备注 `gapped through the stop at the open`。理由：跳空越过止损是按计划执行必然承受的真实亏损；统计复查显示把它作废会让成绩每笔平均虚高约 0.24%。已作废的旧 `gap_stop` 记录由主会话按新规则一次性重算（先备份账本）。
   - 持有期中途的跳空仍按下面的离场规则处理。
2. **离场**（逐日检查，按顺序）：
   - 止损：做多时最低价 ≤ 止损（跳空低开则按开盘价）；
   - 目标：做多时最高价 ≥ 目标（跳空高开则按开盘价）；同一天既触及止损又触及目标时，**按止损处理**（保守）；但开盘价已越过目标时，按开盘价以目标离场（挂单在开盘即成交）；
   - 可证伪条件的机器规则（如"收盘价低于 X"），按收盘价离场；
   - 到期：持有期满的那天收盘离场（持有期按交易日计，加密货币按自然日）。
   - **加密货币（7×24，UTC 日线）按自然日**：成交 K 线必须正好是创建后的第一个 UTC 日；到期日 = 入场日 + 持有期 − 1 天。离场之前的持有窗口里缺任何一天的日线（之后的日线已经有了，说明是缺数据而不是还没到），记录保持未结算，备注 `data gap <日期>`，绝不估算；缺的是离场之后的日子则不影响。
   - 做空全部镜像。
   - **持有期为 1 根 K 线的记录（日内类影子）**：不看止损、目标、可证伪条件，也不适用上面的开盘跳空规则，只按成交价到当天收盘的方向计盈亏和 Brier（所有人决定 2026-09-29：日线分不清同一天先碰止损还是先碰目标）。
3. **成本**：每边成本（基点）按品类配置，默认：股票 / ETF 5 bp 滑点；加密货币 BTC/ETH 100 bp、其他币 125 bp（2026-09-28 按 Robinhood 官方下单说明核实：默认下单点差约 0.96%，其中 0.95% 为返佣；其他币多加 25 bp 为估计）。
4. **盈亏**：净收益 = 方向 × 价格收益 − 双边成本；盈亏金额 = 虚拟仓位 × 净收益。
5. **复权调整**：行情源返回复权价，之后的拆股、分红会让历史价格整体变动。结算前，用「当前序列在快照日的收盘价 ÷ 快照价」得到系数，把入场区间、止损、目标、可证伪价位同比缩放后再模拟，并在结算备注里写明系数；快照和 L3 都只用已收盘的 K 线（加密货币按 UTC 日，美股在纽约 16:00 后；Playground 的快照同样如此）。
   - **只和同一数据源比较**：快照记录了数据源（`quote_snapshots.source`）。当前序列来自另一个数据源（如快照用 yfinance、结算用 Binance）时，两者本来就差几个基点，不是复权，系数取 1，备注 `snapshot source X, settlement source Y (not rescaled)`。偏差小于 5e-4 视为取整误差，不缩放。
   - 结算时用的系数记在 `meta.price_factor`（系数为 1 时不写）：成交价、离场价就在那条序列里。之后再算复盘事实（S9 §3）时，价位乘当前系数，成交价乘「当前系数 ÷ 结算时系数」，保证复盘始终在同一条序列里计算（结算后再拆股，MFE / MAE / 止损距离不变）。
6. **基准**：市场基准（股票 / ETF 用 SPY，加密货币用 BTC-USD，海外用当地指数 / ETF）和领域基准（记录时指定，如板块 ETF），同一持有窗口内持有基准的收益。
   - **方向**：基准这一边跟随记录的方向。超额收益 = 净收益 − 方向 × 基准收益（做多 +1，做空 −1），即"是否跑赢同方向持有基准"；做空记录不再因为大盘涨跌而整体被判输赢。复盘事实里的 `beat_market` 读的就是这个超额收益。
   - **日期对齐**：入场日取基准在该日或之后 3 个自然日内的第一根 K 线，离场日取该日或之前 3 个自然日内的最后一根（例如海外记录配美股 ETF 领域基准，入场或离场日恰逢美国假日）。挪动的日期必须是序列中间的空档（另一侧还有 K 线），所以序列过期或太短时仍记为缺失，不会拿不完整的窗口冒充。
   - **补算与放弃**：已结算记录的基准数据当时缺失的，之后每次结算都会重试补上（只改基准字段和备注里的基准一段，其他备注如复权系数保留）。离场 10 天后基准序列仍在、却没有可对齐的 K 线，备注 `benchmark not comparable: <代码>`，不再重试；取数失败（没有序列）则一直重试。
7. **Brier 分**：结果 = 净收益 > 0 记 1，否则记 0；Brier = (确信度 − 结果)²。
8. **数据不可用**：拿不到日线时保持未结算，并记录"数据不可用"，绝不猜价格（L3 数据诚信）。

### 每个交易时段只提交一次

- 记录的**目标时段** = 它最早能成交的那根日线的日期，与结算的入场规则同一算法（按市场：交易所按当地时间和开盘时间，加密货币和外汇是下一个 UTC 日）；交易所和外汇遇周末顺延到周一（没有交易所假日日历，假日不顺延）。例：周五晚上和周六各跑一次的美股记录都是周一的时段。
- 同一来源（`source_type` + `source_id`）对同一目标时段只能提交一次。第二次提交整体不写入（包括随它一起生成的随机基准），记日志并报告：影子运行报告里状态为 `duplicate`，主管线（`main` / `main_forced`）返回空列表。`main` 和 `main_forced` 是两个来源类型，互不排斥。
- 检查和写入在同一个 SQLite 事务（`BEGIN IMMEDIATE`）里完成，两个进程同时提交也只有一个成功。影子运行在调用 LLM 之前先按同一规则预检，已提交过该时段的影子直接跳过，不浪费调用。

### 并发

- 账本库使用 WAL 模式和 30 秒忙等待，结算、影子、主管线可以在不同进程里同时读写。
- 结算写回是有条件的：未结算记录只在库里仍是 pending / open 时才写，已结算记录的补算只在仍是 settled 时才写。结算读取之后被其他进程改动（例如作废）的记录不会被覆盖，结算报告里单独计数。
- 两个进程同时给旧库补同一列时，"列已存在"的错误忽略，其他错误照常报出。

## 5. 接入

- 主管线：守卫后的交易卡写入账本（`zone` 入场，持有期取卡片的 `max_hold_days`）；没有交易卡时，被迫纸面交易写入账本（`next_open` 入场，持有期 10 个交易日，止损 / 目标取 L3 数值，没有就留空）。
- 每日运行开始时先结算到期记录；另提供 `python marketmind/app.py --mode settle`。

## 5.1 顺带修复

- 交易卡增加 `confidence`（盈利概率 0-1），prompt 要求输出；缺失时账本记 0.5 并标注 `confidence_is_default`。
- 仓位单位：prompt 写明 `position_size_pct` 是百分数（5 = 5%）；若一批卡片仓位全部 ≤ 1，视为小数并换算（live #5 中 Flash 用 0.06 表示 6%，guard 当成了 0.06%）。

## 6. 验收
