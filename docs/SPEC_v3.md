# MarketMind v3 — 产品与架构规格（唯一事实来源）

> 版本：v3.0 ｜ 日期：2026-09-27 ｜ 状态：**所有人已逐条确认决策**（见 `docs/PROJECT_REVIEW_2026-09-27.md` 第 7 节）
> 本规格取代 2026-05 至 2026-06 期间的全部设计文档。旧文档归入 `docs/archive/`，仅供参考；与本规格冲突时，以本规格为准。

## 1. 产品定义

**一句话**：一个人机协作的 AI 投研工作站。系统每天在后台用多源信息和权威一手数据分析市场，由一群彼此独立、以盈利为目标的虚拟基金经理（影子）每天强制做虚拟投资、互相竞争、优胜劣汰。只有在出现大行情时才向所有人发出警报，由所有人在 Robinhood 手动下单。系统对所有人始终是白箱。

**所有人画像与目标**
- 持有美国 Robinhood 账户，本金约 3 万美元。
- 一年中大部分时间持币观望，抓住 3-4 波大行情，只吃中间一段，不冒进，不被套。
- 可以承受较大回撤，但不能承受"没有希望的回撤"，所以**实盘不碰期权**。实盘会投加密货币。
- 前期以模拟为主，影子体系成熟后再上真金白银。

**非目标**
- 不连接券商下单，不自动交易（Law 2）。
- 不做高频交易，不做多用户。

## 2. 系统法则（保留并修订）

| 法则 | 内容 |
|---|---|
| L1 人在回路 | AI 不下单，也不替所有人做决定；方法论变更必须经 Beta 验证并由所有人批准 |
| L2 物理隔离 | 不连券商交易接口，唯一例外是 Robinhood 加密 API 的**只读**持仓同步 |
| L3 数据诚信 | 严禁编造数字；拿不到数据时明确标注"数据不可用"；所有数字都由代码从数据源计算，LLM 不产出价格、指标或仓位数值 |
| L4 反过拟合 | 统计验证只用在晋升评审上；晋升门槛按历史全部试验次数校正 |
| L5 可结算 | 每一条预测都必须可以结算：标的、方向、持有期、确信度、可证伪条件都要写明 |
| L6 白箱 | 所有状态、理由和成绩都可以在仪表盘上追溯到原始记录 |
| L7 空仓有效 | 主管线的"不交易"是正式输出（但当天仍要记录一笔被迫的虚拟交易，见 §5） |

## 3. 标的两层结构

| 层 | 范围 | 用途 |
|---|---|---|
| **可交易层** | Robinhood 美国账户的全部品类：股票（含 24/5）、ETF、期权、期货（股指、能源、金属、外汇、加密货币）、约 30 种加密货币、预测市场 / 事件合约 | 影子的虚拟交易、主管线建议、所有人实盘 |
| **关联层** | Robinhood 没有但会传导过来的资产：A 股 / 港股、日债与日元套利、欧洲利率与股指、农产品现货与期货、利率期货、航运、信用市场等 | 由跨市场传导影子分析；预测对象既包括关联资产本身，也包括它推导出的可交易代理标的 |

- 标的全集由代码维护：美股和 ETF 来自 NASDAQ Trader 官方代码表；加密货币来自 Robinhood 加密 API 的交易对列表；期货、事件合约来自可维护的清单。
- 旧的 `config/asset_universe.py`（写死 25 个标的）作废。

## 4. 总体架构

```
① 数据层（代码）  行情 / 宏观 / 新闻 / 冷门一手数据，按时点保存快照
        ↓
② 证据层          从新闻里抽出可检验的说法 → 用一手数据核对 → 输出"叙事与数据背离"清单
③ 全市场扫描器    代码计算技术面、趋势、异动 → 按领域把候选分发给影子
④ 基准            买入持有（SPY、BTC）、200 日均线规则、各领域随机选、领域 ETF、主 AI
        ↓
⑤ 竞技场          主管线 ｜ 长期影子（约 32 个）｜ 临时影子 ｜ Playground 候选
        ↓
⑥ 统一账本        每一条预测、每一笔虚拟交易、所有人的实盘持仓，到期后自动结算
        ↓
⑦ 评审            晋升阶梯 / 淘汰 / 复盘 / 认知库 /（有数据后）自进化
        ↓
⑧ 顾问与警报      大行情警报 → 所有人拍板 → 在 Robinhood 手动执行
   实盘持仓巡检   亏损分析：离场、持有、还是换标的
⑨ 白箱层          仪表盘 + 内置汇报员（只读）+ Claude Code 定期审计
```

## 5. 主管线

1. 数据与候选：扫描器筛出的候选 + 证据层给出的背离清单。
2. L1 叙事、L2 基本面：由 LLM 解读，只接收代码算好的数据和原文，不自己编数字。
3. L3 技术面：**由代码计算**三灯、支撑阻力、均线、ATR；设计规格 §4.3 的原意在这里恢复。
4. 红队：独立质疑；质疑意见本身也要进入账本，事后评判它说得对不对。
5. 决策输出（结构化）：
   - 交易卡：标的、方向、入场**区间**、离场条件、持有期、确信度、可证伪条件、替代方案；
   - 或"不交易"卡，**当天同时记录一笔被迫的最佳虚拟交易**，用来衡量"不交易"这个判断值多少钱。被迫交易由代码选（所有人 2026-09-29 决定）：L3 绿灯中盈亏比最高者（同分按代码字母序），没有可用候选时做多 SPY；确信度记为"未声明"（0.5 + confidence_is_default），不计入 Brier 平均。
6. 风控由代码强制执行：仓位上限、组合总风险（热度）上限、止损与目标的方向是否合理、相关性。
   - 仓位由代码计算（所有人 2026-09-29 决定）：仓位% = min(25, 单笔风险 1% ÷ 止损距离% × 100)，止损距离 = (入场区间中点 − L3 止损) ÷ 中点；止损距离非正或非有限的卡片直接丢弃。LLM 不给仓位（它写的数字只留档），确信度暂不参与仓位（S9 校准后再议）。
7. DSR/PBO 从每日管线中移除，改用在晋升评审里（§8）。

## 6. 影子生态

### 6.1 原则
- **长期影子的目标是盈利**，不是验证策略。彼此不交流，各自投资，各自优化自己的策略。
- **每日强制决策**：每个影子每天必须给出至少一笔决策，内容包括：标的、方向、工具、持有期、**确信度 0-1**（虚拟仓位按确信度缩放，不确定时最小 $100）、**可证伪条件**。不允许弃权。
- 最小仓位（$100）交易占比超过 60% 时降权（沿用 v4.0）。
- **工具**：影子是虚拟盘，只要在自己的投资领域内，全球市场上真实可交易、并且有行情数据的标的都可以用，不受 Robinhood 限制（所有人 2026-09-28 决定；实现见 `docs/S3_DESIGN.md` §7）。账本记录工具类型和市场；**只有所有人能实际执行的工具才会进入警报**。
- 信息隔离：影子看不到主管线的结论，也看不到其他影子的输出。唯一例外是 ConsensusExtractor（只提供方向标签和百分比，供共识逆向者使用）。
- 影子不投票，也没有决策融合；毕业成为顾问后，意见只提供给警报判断和所有人参考。

| 类型 | 触发 | 寿命 | 用途 |
|---|---|---|---|
| temp_event | 事件检测（E1-E4，取影响最大的前 5 个） | ≤30 天 | 追踪突发事件带来的投资含义；成绩进入账本，用来评估"哪类事件值得跟" |

## 7. 统一账本（系统的脊梁）

每条记录包含：
- 记录编号、来源（主管线 / 影子编号 / 临时影子 / Playground / 基准 / 所有人实盘）；
- 时间戳、当时看到的输入快照编号；
- 标的、层级（可交易 / 关联）、工具、方向；
- 入场规则（下一个可成交价）、持有期；
- 确信度、虚拟仓位、可证伪条件、理由摘要；
- 结算：到期价格、盈亏（扣除成本与滑点）、相对领域基准和市场基准的超额收益、Brier 分、可证伪条件是否触发。

期权、期货按合约规则结算；事件合约按结果结算。所有人的实盘持仓也记入账本，作为"人类决策镜像"。

## 8. 晋升阶梯（唯一标准）

```
候选（Playground / 新影子 / beta）
  → 见习：≥60 个交易日，有效独立样本 ≥ 最短样本期（MinTRL，考虑持有期重叠）；
          扣除成本后跑赢：同领域随机选 + 领域 ETF + 主 AI
  → 正式：参与复合排名（MPPM 35 / Calmar 25 / Omega 20 / 胜率 20，贝叶斯剪发）
  → 顾问：Tier1/Tier2 + 压力测试 + 一段前向样本外期 + CSCV/PBO（T×N 矩阵）
          + 按全部历史试验次数校正的 DSR + 校准（Brier）
  → 持续监控：CUSUM/BOCPD 发现衰退，当天暂停（无任期）
淘汰：连续垫底 → challenger → 替换或恢复
```

具体阈值在实现时按样本量计算后写入配置，并列在仪表盘上。

## 9. 证据层 v1

- 先接入 5 个一手数据源：SEC EDGAR（全文 + XBRL）、FINRA 空头 / RegSHO、纽约联储市场数据、ETF / 稳定币资金流、国债拍卖。
- 流程：新闻 → 抽出可检验的说法 → 映射到一手数据 → 判定为支持 / 矛盾 / 无法验证 → 生成背离清单（进入账本并打分）。
- 同源转载只算一个来源；至少 2 个独立来源才能提高置信度。

## 10. 警报、白箱与汇报

- **大行情警报**（所有人 2026-09-29 决定改版，细则见 `docs/S8_DESIGN.md`）：
  - **主干是代码确认的趋势**：所有人能执行的标的，趋势状态今天从 CASH / WATCH / EXIT 切到 TREND（入场警报，做多）或从 TREND 切出（离场警报）。趋势状态来自可插拔的趋势信号源，默认是每日趋势状态机（`docs/TREND_DESIGN.md`，有精简版清单就用精简版）；改用月度规则只需改配置。
  - **顾问与证据是附注，不是条件**：顾问（含 Playground 顾问；尚无顾问时由全部在册影子与 Playground 候选代投）按资产组投票（持有期 < 10 天的决策不投票）。同向 ≥ 2 票、来自 ≥ 2 个组、反向 ≤ 同向一半 = "顾问支持"；投票者过半方向相反 = "否决标记"（只显示，不拦截）。同资产组、同方向的证据层背离作为支持说明。
  - **观察 / 正式**：默认观察（计算、记报告，入场警报记账本，不推送）；正式推送只由所有人明确打开开关。正式模式下一次运行的所有警报合并成一条优先消息。周末运行也评估加密标的的警报。
- **实盘持仓巡检**（每天）：亏损时分析该不该离场；对比"继续持有的前景"和"换成更好机会的前景"（割肉换标的是否更划算），附上账本证据和替代方案。
- **仪表盘**：今日简报、统一账本、影子竞技场、证据层、主管线推理链、晋升淘汰日志、系统健康。
- **内置汇报员**：只读，每个回答都引用记录编号；拿不到数据就明说。
- **定期审计**：由 Claude Code 执行，包括核对汇报员的发言与数据是否一致。

## 11. 自进化

- 账本攒到约 50-100 条已结算预测之前**冻结**。
- 之后分步启用：校准 → 复盘 → 认知库 → 知识继承。任何方法论变更都要先经 beta 验证，再由所有人批准。
