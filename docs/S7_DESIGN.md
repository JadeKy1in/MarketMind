# S7 设计：影子生态收尾——晋升阶梯 + 临时影子

> 规格来源：`docs/SPEC_v3.md` §6.1、§6.3、§8、§12（C03、C04、C17、C19、C20、C26、C30）。日期：2026-09-28。

> 所有人决定（2026-09-28，第二次）：修正两处统计弱点——"胜过随机"改为蒙特卡洛随机组合基准（§一），变体试验判定改为 40 个交易日 + HAC t 检验 + Holm 校正（§二）。

## 范围

- **做**：晋升阶梯（见习 → 正式 → 顾问 → 持续监控，淘汰 → 挑战者）；四类临时影子（temp_event、missed_path、challenger、beta）；把结果接进账本、仪表盘、警报（顾问名单）。
- **不做**：自进化（S9，SPEC §11 在约 50–100 条已结算预测前冻结）；方法育种、紧急配额、配额浮动（SPEC 冻结）。
- **现实约束**：评审需要账本攒满 60 个交易日，最早约 2026-12。代码现在写好、用模拟数据验证；在此之前每天运行只会显示"见习 x/60"。

## 一、晋升阶梯（`marketmind/promotion/`，纯代码）

### 数据
- 以影子为单位，从账本取 `settled` 记录（净收益已扣成本）。
- **日收益序列**：每笔按退出日记账，当日收益 = Σ pnl_usd / 名义资金（$10,000）。无交易的交易日记 0。
- **有效独立样本数** N_eff：持有期重叠会让样本不独立。N_eff = min(已结算笔数, 覆盖的交易日跨度 / 平均持有期)。

### 阶段与门槛（阈值集中在 `promotion/config.py`，仪表盘列出）

| 阶段 | 进入条件（全部满足） |
|---|---|
| 见习 | 上线即进入 |
| 正式 | 有记录的交易日 ≥ 60；N_eff ≥ MinTRL（Bailey & López de Prado 最短样本期，95% 置信，基准夏普 0，考虑偏度和峰度）；扣成本后平均净收益同时：胜过随机（蒙特卡洛随机组合基准，见下文，单侧 p ≤ 0.05）、高于领域 ETF（平均领域超额 > 0）、高于主管线（同期主管线 + 被迫交易的平均净收益） |
| 顾问 | 正式满 20 个交易日；综合分进入 Tier1（正式影子前 20%）或 Tier2（前 50%）；压力测试（市场基准最差的 10% 交易日里，平均日收益不低于 −2 倍市场基准）；前向样本外期（成为正式后的 20 个交易日净收益 > 0）；CSCV/PBO < 0.3（全部正式影子日收益 T×N 矩阵，16 个分块）；DSR ≥ 0.95（试验次数 = 历史上全部影子 + 挑战者 + beta 的总数）；校准：平均 Brier < 0.25 |
| 暂停 | 顾问的日收益 CUSUM 报警（均值下移 0.5 个标准差、阈值 5 个标准差）→ 当天暂停，从顾问名单移除，回到正式；无任期 |

- **综合分**：MPPM（ρ=3）35%、Calmar 25%、Omega（阈值 0）20%、胜率 20%。每项先在正式影子间转成百分位排名再加权。**贝叶斯剪发**：分数向全体均值收缩，权重 n/(n+k)，k = 30 笔。最小仓位（≤ $100）交易占比 > 60% 的影子综合分 × 0.8（SPEC §6.1）。
- **C20 较严门槛**：PBO < 0.3、DSR ≥ 0.95。
- **C04**：数据不足前不评等级——不满足见习门槛的影子不参与排名。

### "胜过随机"门槛：蒙特卡洛随机组合（`promotion/random_mc.py`，纯代码）

**为什么改**：账本里的随机基准影子（`random:<影子>`）每天只抽 1 笔 $100 交易，拿影子均值和它的均值比，几乎是抛硬币——随机基准自身的噪声和影子一样大，"高于随机"对真实能力几乎没有区分力。

**规则**（对每个影子，每个评审日）：
- 取该影子全部已结算记录（与"平均净收益"同一批），生成 1000 个随机组合（`MC_DRAWS`）。每个组合与影子逐笔对应：**笔数相同、每笔的入场日和退出日相同**（因此实际持有期相同）；**多空比例相同**（影子的方向序列在各笔之间随机重排，方向择时不白送）；标的从该影子的**标的池**里等概率抽取。
- **标的池** = 名册观察清单（随机基准影子就是从当天上下文的标的里抽，即 `sorted(ctx.closes)`，其主体是观察清单）∪ 随机基准影子历史上实际抽到过的标的（覆盖新闻猎手、空头追踪等每天临时加入的标的）。
- **每笔收益** = 方向 ×（退出日及之前最后一根日线收盘 / 入场日及之后第一根日线开盘 − 1）− 2 × 单边成本；成本直接用账本规则 `settlement.cost_bps`（资产类型按 `recorder.classify_ticker`，与随机基准记录一致）。
- **判定**：影子平均净收益 ≥ 随机组合均值分布的 95% 分位（`MC_QUANTILE`），且单侧 p = (1 + 随机均值 ≥ 影子均值的次数) / (1 + 有效次数) ≤ 0.05（`MC_ALPHA`）。
- **缺数据一律判不通过（fail closed）**：池里完全没有日线的标的剔除并列出；超过一半标的没有日线 → "不可评估"；某次抽样抽到的标的在该笔窗口内缺线（窗口首 / 末根日线离入场 / 退出日超过 4 个日历日，`MC_MAX_GAP_DAYS`）→ 这次抽样作废，报告有效次数；有效次数 < 200（`MC_MIN_VALID`）→ "不可评估"。
- **可复现**：随机种子 = sha256(影子编号 + 评审日期)，同一天同一账本重跑结果不变。
- **何时计算**：只对见习阶段、且"有记录的交易日 ≥ 60"的影子计算（只有它们可能因此晋升）；其余见习影子显示"未评估"。正式 / 顾问影子沿用晋升当天的结果。详情写在 `state.json` 每个影子的 `random_mc` 字段（有效次数、95% 分位、p、缺线标的）。
- **日线来源**：`run_promotion` 默认用账本的 `HistoryPriceSource`，与结算、影子运行共用同一进程的价格缓存，日常运行时基本不再联网；未缓存的标的最多 4 路并发、总时限 120 秒（`MC_FETCH_BUDGET_S`），超时的按缺数据处理。测试和回放传入静态价格源，完全离线。
- **耗时**：模拟本身是向量化的；40 个影子 × 每个 300 笔 × 15 个标的实测约 0.8 秒，每个 1000 笔约 2.5 秒（不含取数）。
- 账本里的随机基准影子**照常运行**（仪表盘、白盒页仍在用），其均值仍作为 `random_mean_net` 列出，但不再参与门槛。

### 淘汰 → 挑战者（C30）
- 评估期 = 20 个交易日。正式影子连续 3 个评估期综合分在后 20% → 自动发起挑战者试验（见下）。
- 状态文件 `data/promotion/state.json`：每个影子的阶段、各项指标、最近一次评估；事件日志 `data/promotion/events.jsonl`（晋升、暂停、恢复、挑战）。
- 顾问名单写 `data/advisors.json`，S8 警报读取后自动从观察模式转为正式模式。

## 二、临时影子

所有临时影子的决策都进账本：`source_type = temp_shadow`，`source_id` 带类型前缀。它们与长期影子一样只看新闻和行情，看不到主管线结论（C26）。

### temp_event（事件影子，最多同时 5 个，寿命 ≤ 30 天）
- **事件检测 E1–E4**（沿用旧定义）：E1 央行意外、E2 地缘政治、E3 波动率冲击、E4 关键人事变动。
  - E1、E2、E4：关键词先筛新闻，再用 1 次 Flash 调用把同一事件的报道归并成事件（给出类型、标题、涉及市场）；代码校验新闻编号，并要求 ≥ 2 个独立来源。
  - E3：纯代码。长期影子观察清单里的标的，最近一日收益绝对值 ≥ 过去 60 日日收益标准差的 4 倍。
  - 影响分 = 类型基础分（E1 0.6、E2 0.5、E3 0.7、E4 0.4）+ 0.1 × 独立来源数（上限 +0.3）；E3 按倍数加分。
- 每天按影响分从高到低补位，直到活跃事件影子达到 5 个；与活跃事件同类型且标题 / 标的高度重合的不重复生成。
- 事件影子每天和长期影子一样做强制决策（同一套上下文与校验），方法论 prompt 由模板 + 事件描述生成。满 30 天自动退役。
- 仪表盘按事件类型汇总成绩，用来回答"哪类事件值得跟"。

### missed_path（纯代码，不花 token，寿命 30 天，只读）
- 每天主管线决策后：L2 候选和 L3 绿灯里**没有做成交易卡**、且所有人可执行的标的，各记一条虚拟做多（下一个开盘价入场，持有 30 个交易日，$100，确信度 0.5 默认值）。`source_id = missed_path:main`。
- 被所有人拒绝的大行情警报：警报自己的账本记录照常结算（S8 已实现），仪表盘单列。

### challenger 与 beta（合并为一套"变体试验"，C19；与事件影子分开计数，最多同时 5 个）
- **发起**：challenger 由淘汰规则自动发起；beta 由所有人发起（`python -m marketmind.shadows.trials propose <影子> --note "改动说明"`），或名册出现空缺时发起。
- **变体生成**：1 次 Flash 调用，输入原方法论、改动说明、该影子的账本成绩摘要，输出修改后的完整方法论（仍须保持 8 段模板）。代码检查格式后保存在 `data/trials/<编号>/prompt.md`。
- **运行**：变体与原影子看同样的上下文，每天各自决策，`source_id = trial:<编号>`；challenger 与 beta 的试验窗口都是 **40 个交易日**（`TRIAL_BARS`，原为 10）。同时运行上限仍是 5 个（按"运行中"状态计数，与窗口长度无关），但每个试验占位约 40 个交易日再加最长持有期的结算等待，名额周转会慢约 4 倍。
- **判定**（所有人决定 2026-09-28）：试验窗口结束且窗口内决策的记录全部结算后（或窗口结束超过 60 天仍未结算完），
  1. **配对序列按退出日对齐**：原影子和变体各自把已结算记录的 pnl_usd 记在退出日、除以名义资金 $10,000（与晋升阶梯的日收益同一口径）；在交易日历上（账本全部已结算记录的退出日 ∪ 双方自己的退出日）从双方最早退出日到最晚退出日逐日相减（变体 − 原影子），无退出的日子记 0。退出日数据账本里都有，不需要退而求其次用决策日对齐。
  2. **主检验**：对差值序列做单侧 **HAC（Newey–West，Bartlett 权重）t 检验**，即 Diebold–Mariano 检验；滞后阶数 = 原影子窗口内决策持有期的中位数 − 1，至少 1（持有期重叠使相邻日的盈亏相关）；参照分布用自由度 n − 1 的 t 分布（小样本修正，Harvey–Leybourne–Newbold 1997 的做法）。
  3. **Holm 校正**：同一次评审里判定的全部试验（有 p 值的）构成一个族，按 Holm 逐步法调整 p 值；**调整后 p ≤ 0.05** 且平均差 > 0 判"通过"，否则"未通过"。差值毫无波动（无法检验）判"未通过"并注明。
  4. **最少配对天数 30**（`MIN_PAIRS`，原为 5）；不足判"样本不足"。
  5. Wilcoxon 符号秩检验只作为稳健性统计量写进结果（`wilcoxon_p`），**不参与判定**。
- **为什么改**：原方案 10 个交易日、最少 5 对、p < 0.10 的单侧 Wilcoxon，研究模拟里检验功效约等于显著性水平本身，通过的试验里约一半到七成是假阳性；而且忽略了持有期重叠造成的相关。
- 结果字段：`pairs`、`mean_diff`（日盈亏差 / $10,000）、`lag`、`t_stat`、`se`、`p_value`（HAC 原始单侧 p）、`p_holm`、`holm_family`、`wilcoxon_p`、`first_day`、`last_day`。白盒页照常显示 `pairs`、`mean_diff`、`p_value`，注意 `mean_diff` 的含义已从"每笔平均净收益差"变为"每日盈亏差占名义资金的比例"。
- **L1 人在回路**：通过的试验只标记"待批准"。所有人 `python -m marketmind.shadows.trials approve <编号>` 后，才把变体方法论写回 `shadows/v3/prompts/<影子>.md`（先备份，改动进入 git 由所有人提交）；`reject` 则结束。

## 运行顺序（每日）

结算 → 新闻 → 长期影子 + 活跃临时影子（后台）+ 证据层（后台）→ 主管线 → missed_path 记录 → 等待影子 → 持仓巡检 → **晋升评审** → 警报（读最新顾问名单）。
事件检测在新闻抓完后执行，新事件影子当天就参与决策。

## 实现说明（2026-09-28）

- 代码：`marketmind/promotion/`（config / metrics / ladder / runner）；`marketmind/shadows/v3/`（temp_event、missed_path、trials，事件影子方法论模板 `prompts/_temp_event.md`）。
- 试验命令行：`python -m marketmind.shadows.v3.trials {list,propose,approve,reject}`。
- 口径细节：
  - MinTRL 按每笔净收益计算（与 N_eff 按笔计数一致）；DSR、PBO、CUSUM、综合分用日收益序列。
  - 压力测试的市场日收益 = Σ(仓位 × 该笔的市场基准收益) / $10,000，按退出日记；只取有市场暴露的交易日中最差的 10%，不足 10 天判不通过。
  - "有记录的交易日"按影子决策日去重计数。
  - 后 20% 向下取整、前 20% / 50% 向上取整：排名影子少于 5 个时没有垫底组。
  - 顾问被 CUSUM 暂停后，下一个评审日回到正式，正式天数与前向样本外期重新计算。
  - DSR 的夏普方差取全部在线影子日夏普的方差；不足 2 个影子时用该影子自身的估计量方差。
  - 与主管线比较时，只取该影子首笔到末笔退出日之间结算的记录（随机基准影子的同口径均值仍列为 `random_mean_net`，仅供参考）。
  - 正式影子少于 2 个时 PBO 无法计算，判不通过（C20 较严门槛）；正式影子不降级；漏跑的评估期逐次追补。
- 每日运行：长期影子运行前生成事件影子并加载运行中的试验；主管线记账后记录 missed_path；持仓巡检后执行晋升评审、判定到期试验、为"挑战"事件发起挑战者；最后跑警报（读取 `data/advisors.json`）。

## 现实预期（2026-09-28）

- **晋升很慢是正常的**（推断，来自研究阶段的模拟，未用真实账本验证）：在 MinTRL 与 60 个交易日的门槛下，年化夏普为 1 的影子在 60 天时通过的概率约 1%；年化夏普低于 2 的影子，一年内大概率到不了正式。第一批评审（约 2026-12）看到"全部仍在见习"不代表代码有问题。
- **试验检验在小样本下仍偏宽松**（本次实现时的模拟，`marketmind/tests/test_promotion/test_paired_stats.py` 覆盖了其中一种情形）：40 个交易日、持有期重叠按等权 MA(h−1) 这种最坏情况模拟，名义 5% 的 Newey–West t 检验实际误判率约为：持有 5 天 12%、10 天 16%、20 天 25%（不做 HAC 修正会更高）。持有期越长，40 天里独立的信息越少。若要进一步压低假阳性，可选：fixed-b 临界值（Kiefer–Vogelsang 2005）、按持有期延长试验窗口，或只对持有期 ≤ 5 天的影子做试验——需所有人决定，目前未实施。
- 试验按各自的结束日判定，同一天结束的试验通常只有 1 个，所以 Holm 族往往只有 1 个成员（此时等于不校正）；多个试验同一天结束时才起作用。
