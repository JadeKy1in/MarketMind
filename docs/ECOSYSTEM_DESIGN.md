# 影子生态健康监测（纯代码）

> 规格来源：`docs/SPEC_v3.md` §6（影子生态、信息隔离、C16 集中度、C26 零通信）、§8（晋升阶梯的独立性假设）；`docs/S7_DESIGN.md`（日收益口径、临时影子）。
> 所有人决定（2026-09-29）：在统一账本上重建已删除的旧"生态健康"功能。
> 代码：`marketmind/ecosystem/`（`config.py` 阈值、`health.py` 纯函数、`runner.py` 读写、`__main__.py` 命令行）；测试：`marketmind/tests/test_ecosystem/`。

## 一、定位

- **只监测，不干预**：不改任何决策、晋升、挑战者或警报，也不推送通知。结果写入 `data/ecosystem/<纽约日期>.json`，供仪表盘、日报和定期审计读取。
- **纯代码**：不调用 LLM；账本以只读方式打开（SQLite `mode=ro`），账本不存在时不会创建。
- **每日运行**：`pipeline/orchestration.py::ecosystem_step`，在警报之后、日报之前；失败时捕获异常，计入 `[degraded]` 列表（与其他步骤相同）。
- 手动运行：`python -m marketmind.ecosystem [--day YYYY-MM-DD] [--data-dir DIR] [--dry-run] [--json]`。

## 二、数据口径

| 项 | 定义 |
|---|---|
| 记录范围 | 账本 `shadow`、`temp_shadow`、`playground` 三类来源 |
| 决策者 | 上述记录去掉 `missed_path:*`（由主管线代码生成、永远做多，不是独立判断者） |
| 投票者 | 决策者再去掉 `trial:*`（变体与原影子看同一份上下文；计入相关性检查并标记"预期内"，但不在羊群检查里重复投票） |
| 记录日 | `meta.run_date`，没有时取 `created_at` 的纽约日期 |
| 完整运行日 | 当天提交记录的长期影子 ≥ 在册活跃影子的 50%。周末只跑加密影子，不算完整运行日，因此不会打断工作日的连续计数 |
| 回看 | 最近 60 个完整运行日 |
| 资产组 | `alerts/asset_groups.py`（与顾问投票同一映射；未列出的标的自成一组） |
| 每日盈亏 | 与晋升阶梯相同：已结算记录按退出日记账，当日 = Σ pnl_usd ÷ $10,000，无退出的交易日记 0；交易日历 = 全账本已结算退出日 ∪ 决策日 |
| 名册 | `roster.active()`（活跃）与 `roster.all_entries()`（含接任者），退役信息来自 `promotion/retirements.json` |

## 三、六项检查与阈值

旧模块从未在真实数据上运行过，下面的阈值按现有账本结构重新推导；全部集中在 `ecosystem/config.py`，报告文件的 `thresholds` 字段原样列出。

### 1. 羊群 / 方向集中（旧 collusion_detector + concentration_detector）

- 每个完整运行日、每个资产组：每个投票者在该组的**净方向**（多 +1、空 −1 相加后取符号，净为 0 的不计）。
- **集中**：投票者 ≥ 4 且同向占比 ≥ 80%。**标记**：同一方向连续 ≥ 3 个完整运行日，且这几天逐日双侧二项 p 值（零假设：各自独立抛硬币）的乘积 ≤ 0.01；最新一天必须是今天，更早结束的记为 `episodes`（历史片段）。连续 ≥ 10 天标 `escalate`（沿用旧设计的"升级审查"，只显示）。
- **理由**：80% / 3 天沿用旧设计。旧设计按单个标的计票；现在 31 个影子领域各不相同，同一资产组一天通常只有 2–6 票，所以加最少票数和联合 p 值：4 票全同向的日 p = 0.125，连续 3 天 = 0.002（通过）；5 票 4:1 的日 p = 0.375，连续 3 天 = 0.053（不通过）；3 票即使全同向 3 天也只有 0.016。这样在不同票数下误报率一致，而不是只看一个百分比。
- **市场驱动还是行为羊群**（替代旧的"市场信号强度 0.70"）：读当天 `data/trend/<日期>.json`（全量清单）把成员标的的状态汇总成组状态——任一成员 TREND → TREND；所有有数据的成员都是 CASH / EXIT → CASH；其余为 WATCH。一致做多且组状态 TREND、或一致做空且组状态 CASH，判为**市场驱动收敛**；其余有状态的判为**行为羊群**；没有趋势数据的判为"无法区分"。一段连续期取多数（平票按行为羊群）。注意：趋势状态机只做多，CASH 只表示"不在上升趋势"，不是下跌趋势，所以做空的"市场驱动"判定偏弱。
- **C16（按市场状态动态调整阈值）**：没有照搬旧的 RANGE_BOUND 70% / CHOPPY 95% 表——那些阈值从未验证，而且依赖一个已不存在的 ADX 状态分类器。现在用"趋势状态是否与共识一致"来区分，阈值保持固定；若以后要动态阈值，在 `config.py` 里按组状态分档即可。
- 另列 `ecosystem_long_share`：每天投票者整体净做多的比例，只展示。

### 2. 输出相关 / 多样性（旧 diversity_controller 第 3 层）

- **盈亏相关**：两两 Pearson 相关，按每日盈亏序列在双方存续期重叠的交易日上计算；重叠 < 20 天或任一方无波动的对，相关记 0（视为独立）。
- **有效独立影子数 N_eff**：基于特征值的参与率 N_eff = (Σλ)² / Σλ² = N² / ‖R‖²_F。完全独立 = N，完全相同 = 1。只统计有 ≥ 20 天盈亏序列且有波动的决策者（报告为 `N_eff x/y`，y = 合格数）。
- **近似重复簇**：ρ ≥ 0.8 且共同天数 ≥ 20 的对连成簇（并查集）。与晋升 DSR 的试验聚类（`promotion.metrics.effective_trials`，ρ ≥ 0.5 平均连接）是两回事：那边问"算几次试验"，这边问"是不是同一个影子"，所以取更严的 0.8。
- **方向向量**：每个决策者每个完整运行日一个向量（资产组 → 净方向 ±1，没做为 0）。两两余弦相似度在共同运行日上计算（需 ≥ 20 天）；领域不重叠的影子余弦为 0，这是真实的"不相关"，所以方向 N_eff 也纳入这些对。方向重复簇要求余弦 ≥ 0.8 **且**双方都下注的格子 ≥ 20 个，避免两个影子只重合几次就被判重复。
- 同一谱系（变体 `trial:*` 与原影子、接任者 `x@2` 与 `x`）组成的簇标记 `expected: true`，不计入摘要里的重复簇数。

### 3. 信息源同质化（旧 concentration_detector"BlackRock 警告"）

- **新闻来源（2026-09-29 起已记录）**：影子运行器在决策时写入 `meta.news_sources`（影子上下文里各条标题的来源名，去重排序）。监控对每个影子统计近 N 天最常看到的来源，给出"主导新闻源"份额（≥ 50% 标记）和影子之间来源集合的平均 Jaccard。更早的记录没有这个字段；窗口内全部记录都没有时仍报 `not_recorded`。
- **现有可算的替代维度**（最近 20 个完整运行日，每个决策者取出现最多的那个值）：
  - 主导资产组、主导标的：同一主导值的决策者占比 ≥ 50% 标记（沿用旧的 50% 阈值）；
  - LLM（`meta.llm`；`meta.model` 是档位 "flash"，不是模型，不用）：同一模型占比 ≥ 50% 标记——同一个模型的系统性偏差会同时进入所有影子；
  - 两两标的集合的平均 Jaccard，只展示。

### 4. 停滞 / 平台期（旧 plateau_detector，改为只看行为）

- 旧版依赖层级、胜率和"洞察"记录，v3 已不存在。现在只看决策本身：
  - **重复**：最近 20 个决策日（至少 10 个）里，出现最多的"标的 + 方向"占全部决策 > 80%。
  - **平台期**：需要满 20 个决策日，分成前后各 10 天：两半的标的集合 Jaccard ≥ 0.8，**且**平均确信度变化 ≤ 0.02，**且**整个窗口确信度标准差 ≤ 0.03。确信度按两位小数报告，真实账本当前全部记录的确信度均值 0.563、标准差 0.035，所以 0.02 / 0.03 表示"几乎不动"。
- 暂定值：账本只有 3 天，尚无法用数据校准；满 40 个交易日后应复核。

### 5. 僵尸 / 完整性（旧 zombie_detector，不再自动处理）

- **僵尸**：`roster.active()` 里的影子在最近连续 ≥ 3 个完整运行日没有任何记录（接任者从批准日之后开始计）。3 天 = 一个短周末加一天，足以排除偶发的单次失败。
- **孤儿**：账本里的 `shadow` 来源不在 `roster.all_entries()`；`playground` 来源没有对应的 Playground 清单；`temp_shadow` 前缀不是 `temp_event:` / `trial:` / `missed_path:`，或 `trial:` 不在 `trials.json`。任何一项来源读不到时跳过该项并写入 `notes`。
- **退役后仍提交**：已批准退役的影子在批准日之后仍有记录。
- 旧版会"自动退役僵尸"；现在只报告（L1 人在回路）。

### 6. 整体退化趋势（旧 ecosystem_health，只报告不行动）

- **投票熵**：每个完整运行日，全部投票者记录的多空二元熵（0–1 比特）；以及"分散度" = （资产组, 方向）格子分布的熵 ÷ log₂(记录数)。
- **跑赢随机基准的比例**：每 5 个交易日取一个 20 个交易日滚动窗口（按退出日），影子和它的随机基准（`benchmark` 来源 `random:<影子>`）在窗口内都有 ≥ 5 笔已结算记录才算合格，合格影子 ≥ 5 个才出一个点；指标 = 平均净收益高于随机基准平均的影子占比。
- **Mann–Kendall 趋势检验**（至少 10 个点，双侧 α = 0.05，含并列修正与连续性修正）：分别检验熵、分散度、跑赢比例。滚动窗口有重叠，p 值偏乐观，所以只报告，不触发任何动作。
- 旧版的 token 效率趋势不在范围内（token 用量不在账本里）。

## 五、输出与读取接口

- 文件：`data/ecosystem/<纽约日期>.json`（临时文件 + `os.replace` 原子写入，Windows 下被读者占用时重试）。顶层字段：`version`、`date`、`written_at`、`population`、`herding`（`flags`、`episodes`、`today`、`ecosystem_long_share`）、`diversity`（`pnl`、`direction`：`eligible`、`n_eff`、`pairs_high`、`clusters`）、`homogenisation`、`stagnation`、`integrity`（`zombies`、`orphans`、`retired_submitting`）、`degradation`、`thresholds`、`notes`、`summary`。
- 仪表盘 / 日报读取：`marketmind.ecosystem.read_report(day: str | None = None, root: str | Path | None = None) -> dict | None`——`day` 为空时返回最新一份（跳过损坏文件），没有时返回 None；`root` 默认 `MARKETMIND_DATA_DIR` 或 `data`。一行摘要在 `summary`。
- 管线打印一行：`[ecosystem] herding: ..., N_eff x/y, dup clusters k, zombies z`（有孤儿、退役仍提交、同质化或停滞时追加在后面）。

## 六、以后如何接入顾问投票的独立性假设（未实现，需所有人决定）

S8 警报的"顾问支持"要求同向 ≥ 2 票、来自 ≥ 2 个组，隐含假设是顾问彼此独立；晋升阶梯的 DSR 也按独立试验数校正。这里的结果可以在数据足够后用于：

1. **按簇计票**：同一个近似重复簇（盈亏 ρ ≥ 0.8）里的顾问只算 1 票，"≥ 2 个组"改为"≥ 2 个簇"。
2. **行为羊群时降级**：某资产组当前有"行为羊群"标记时，该组的顾问支持只显示、不算"支持"。
3. **生态级提示**：盈亏 N_eff / 合格数 < 0.5（一半以上的影子实际上是重复的）时，在警报附注里提示"顾问意见独立性不足"。

以上三项都会改变警报判定，按 L1 需要所有人批准后再实现；在此之前本模块只输出数据。

## 七、局限

- 账本只有 3 天，多样性、停滞、退化三项要到约 20–40 个交易日后才有结论；阈值届时应按真实分布复核。
- 新闻源同质化缺少数据（见 §三.3 所需字段）。
- 羊群的"市场驱动"判定依赖趋势文件；趋势状态机只做多，做空共识的判定偏弱。
- 联合 p 值假设各日独立、各影子 50/50，实际影子普遍偏多（整体净做多约 70%），所以 p 值只用于统一不同票数下的门槛，不作概率解释。
