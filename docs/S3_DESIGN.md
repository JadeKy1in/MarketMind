# S3 设计：影子接入真实数据 + 每日强制决策 + 基准 + 名册统一

> 依据：`SPEC_v3.md` §6、§7、§13（S3 验收：每天自动产出可结算预测）。日期：2026-09-28。
> 现状盘点结论见本文 §2。所有人已定（2026-09-28）：首批 23 个影子（15 个专家补全 prompt + 8 个动量 / 逆向）；影子一律用 Flash；采用 §3.1 新运行器；每天 1–3 笔、仓位 $100–$1,000；scalper 用日线近似上线（账本注明）。

## 1. 范围（Scope Anchor）

- **目标**：每个在册且 prompt 完整的影子，每天基于真实行情做出至少 1 笔决策，写入统一账本，由 S2 的结算自动打分；同时每天生成基准记录，供以后比较。
- **纳入**：
  - 名册单一来源（32 个 ID，标注上线状态）；
  - 15 个专家 prompt 补全；
  - 每日决策运行器（真实行情上下文 → Flash → 校验 → 账本）；
  - 同领域随机基准；
  - 关掉 SPEC 已冻结、但仍在运行的模块；
  - 信息隔离修复。
- **不纳入**（后续阶段）：
  - 缺失的 9 个影子的 prompt 设计（逐个与所有人确认后再加）；
  - 期权、期货、事件合约决策（账本还不能结算）；
  - 临时影子（temp_event / missed_path / challenger / beta，S7）；
  - 排名、晋升、仪表盘改造（S4 / S7）；
  - 自进化（S9）；
  - 删除旧模块（只停用，另行清理）。
- **扩展需确认**：任何触及"不纳入"项的改动，先问所有人。

## 2. 现状（2026-09-27 盘点）

- 生产跑的是旧名册 24 个（16 专家 + 8 敢死队），prompt 以 `data/shadows/shadows.db` 里的副本为准。
- 影子的行情输入永远为空：5 个调用点都传 `market_data={}`。Flash 调研调用的方法不存在，异常被吞。
- 决策没有工具、持有期、可证伪条件，允许弃权。每个影子每天 1 次 Pro（max 推理），和主管线共用 30 次/天的 Pro 额度，额度用完时静默产出 0 个决策。
- `virtual_trades` 和每日收益从未写入，所以排名、挑战者、毕业一直在空数据上计算。影子不写统一账本。
- 方法育种、紧急配额、AEL 季度复盘被 SPEC 冻结，但仍在运行；catfish 仍能被实例化；L1 用户观点通过 broadcast 泄漏给部分影子。

## 3. 方案

### 3.1 架构：新的精简运行器，旧生态停用（已定）

新增 `marketmind/shadows/v3/`：

| 模块 | 职责 |
|---|---|
| `roster.py` | 名册单一来源：32 个 ID、分组、领域、观察清单、领域基准 ETF、prompt 文件、状态（active / pending_prompt） |
| `prompts/<id>.md` | 每个影子一份方法论 prompt（统一模板，见 §3.3） |
| `context.py` | 由代码生成每个影子的行情上下文（见 §3.4） |
| `decision.py` | 决策 schema、解析、校验（见 §3.2） |
| `runner.py` | 每日运行：并发调用 Flash → 校验 → 写账本；再生成基准记录 |

- 旧的 `ShadowMother` 链路在每日运行中**不再调用**。代码保留，由 `ShadowSettings.legacy_ecosystem_enabled=False` 关闭，约 500 个旧测试不受影响。
- 旧库中不在新名册里的影子（lever_hunter、herd_fader、trend_chaser、sector_spinner、depth_diver、catfish）不迁移。
- 取舍：改造旧 `ShadowAgent` 可以复用等级、配额等外围功能，但它依赖的快照、虚拟交易表都是空的，而且层层吞异常。新写更小、更容易验证，账本作为唯一成绩来源（SPEC §7）。

### 3.2 每日决策（SPEC §6.1）

每个影子每天输出 1–3 笔决策（JSON），字段如下：

| 字段 | 规则 |
|---|---|
| `ticker` | 必须在标的全集中可交易且可结算（股票 / ETF / 加密） |
| `direction` | `long` / `short`，**不允许弃权** |
| `hold_days` | 1–60 个交易日（加密按自然日） |
| `confidence` | 0–1，盈利概率 |
| `falsifier` | 文字，"如果……就说明我错了"，必填 |
| `falsifier_rule` | 可选，`close_below` / `close_above` + 价位，方向必须合理 |
| `stop` / `target` | 可选，做多时必须满足 stop < 现价 < target（做空镜像） |
| `thesis` | 一句话理由 |

- 入场：下一根日线开盘价（`next_open`）。
- 虚拟仓位按确信度缩放：confidence ≤ 0.5 时为 $100；0.5 → 1.0 线性增加到 $1,000。
- 校验失败：带着错误信息重试 1 次；仍失败则当天记为"未交卷"（写日志和运行报告，不写账本，也不编造决策）。
- 单笔不合格（例如标的不可交易）只丢弃那一笔。当天一笔都没有 → 未交卷。

### 3.3 Prompt 模板（每个影子一份）

1. 身份与领域；
2. 观察清单与可交易范围；
3. 信号：看什么数据、怎么解读；
4. 入场规则；
5. 离场 / 持有期规则；
6. 可证伪条件怎么写；
7. 确信度校准要求；
8. 禁止事项（不许编造数据；只用给定的价格和新闻）。

输出格式由运行器统一附加，各 prompt 不重复。15 个专家 prompt 按模板补全；8 个动量 / 逆向影子的现有 prompt 迁入模板。

### 3.4 行情上下文（真实数据，代码计算）

- 观察清单（每个影子约 8–15 个标的）经 `price_history` 取日线，复用 L3 的 `compute_snapshot`，只用已收盘 K 线。给出：收盘价、1/5/20 日涨跌、200 周均线位置、ATR14、L3 灯色、支撑 / 阻力。
- 新闻：按领域关键词筛选当天 Scout 的标题（沿用专家影子的筛选逻辑），最多 20 条。
- 宏观：`fred_client.get_fred_for_shadow`（已按影子 ID 配好）。
- 数据取不到的标的明确标为"无数据"，不估算。

### 3.5 信息隔离

- 影子看不到主管线结论、L1 用户观点和其他影子的输出，broadcast 不再注入。
- 唯一例外：fade_master 读取 ConsensusExtractor 给出的前一天其他影子方向统计（只有方向标签和百分比）。

### 3.6 基准（SPEC §8 见习门槛的对照组）

- **领域 ETF**：每条影子记录带 `domain_benchmark`（名册里配置），由结算自动计算超额收益。
- **同领域随机选**：每个领域每天一条 `source_type=benchmark` 记录，从该领域观察清单里随机选一个标的，方向随机，持有期取该领域影子当天决策的中位数。随机种子 = 日期 + 领域，可复现。
- **主 AI**：主管线的账本记录（`main` / `main_forced`），按领域比较时在 S7 实现。

### 3.7 运行与成本

- 在 `run_daily` 中后台运行（和现在的位置一样）；另有 `--mode shadows` 单独运行。
- 并发 5，每个影子每天 1 次 Flash 调用（校验失败再多 1 次），token 用量计入 `shadow:<id>` 阶段。
- 预计 23 次调用 × 约 1–2 万 token，每天约 25–45 万 token，以第一次 live 实测为准。

### 3.8 停用冻结模块（SPEC §6.3 / §11 / C15 / C21）

新运行器不调用以下模块；旧链路整体关闭后，这些模块也不会再运行：method_breeding、emergency_quota、AEL 季度 / 月度复盘、crystallization、catfish、broadcast 注入。

> 2026-09-28 清理：catfish、AEL 季度 / 周度复盘及约 25 个零引用的旧影子模块已删除；交互模式也改为只在 `legacy_ecosystem_enabled=True` 时启动旧生态（默认改跑 v3 影子，只看新闻和行情），并停止向影子写 broadcast。其余旧模块（ShadowMother 链路约 28 个）现在只在打开旧开关时运行，暂时保留，是否删除待所有人决定。

## 4. 验收

1. 离线测试：名册完整性（32 个 ID、23 个 active 都有 prompt 文件）；决策 schema 校验（缺字段、弃权、不可交易标的、止损方向错误、确信度越界）；重试与未交卷；仓位缩放；随机基准可复现；信息隔离（prompt 中不出现主管线或其他影子内容）；账本写入字段完整。
2. 一次 live（Flash）：23 个影子中 ≥ 90% 交卷，每条记录都能通过账本校验，并在 token 汇总里记录实际用量。
3. 次日结算能推进这些记录（pending → open）。

## 7. 影子交易范围放开到全球（2026-09-28 所有人决定）

- **规则**：影子是虚拟盘，不受 Robinhood 限制。只要在该影子的投资领域内，全球市场上真实可交易、并且有行情数据的标的都可以记录。指数本身不可交易，要用对应的 ETF 或期货表达。**给所有人的警报仍然只列所有人能实际执行的工具**（SPEC §6.1 不变）；主管线的交易卡规则也不变。
- **代码写法**：统一用 Yahoo 风格，例如 `0700.HK`、`600519.SS`、`7203.T`、`SAP.DE`、`CL=F`、`EURUSD=X`、`BTC-USD`。
- **市场模型**（`marketmind/markets.py`）：按代码后缀识别交易所，给出时区、开收盘时间、单边成本、市场基准。
  - 结算的首根可成交 K 线，按交易所当地时间判断；"已收盘 K 线"也按当地收盘时间判断。加密货币和外汇按 UTC 日。
  - 市场基准：美股 SPY；港股盈富基金 2800.HK；A 股沪深 300 ETF（510300.SS）；日股 TOPIX ETF（1306.T）；欧洲各国用本国指数；加密货币 BTC-USD；商品期货 DBC；外汇和利率期货以现金为基准（基准收益记 0）。
  - 单边成本：美股 5 bp，海外股票 10 bp，期货和外汇 2 bp，加密货币 BTC/ETH 100 bp、其他币 125 bp（2026-09-28 更新，见 S2_DESIGN）。
- **行情备选**（按顺序尝试，取不到就暂不结算，绝不估算）：
  - 美股：Alpaca → Yahoo → Nasdaq；
  - 港股、A 股：Yahoo → 腾讯 → 东方财富（2026-09-28 东方财富各主机均报 RemoteProtocolError，改为腾讯优先）；港股发给 Yahoo 时用 4 位代码（09866.HK → 9866.HK），账本仍记原代码；
  - 期货、外汇、全球指数：Yahoo → 东方财富；
  - 日股、欧股：Yahoo → Twelve Data；
  - 加密货币：Yahoo → Binance → Bybit → Coinbase Exchange（公开日线，美元报价，单次最多 300 根，按年份分页回溯）。
  - 东方财富、腾讯是非官方接口，可能变动；账本按标的记录数据来源。
  - **Twelve Data**（`TWELVEDATA_API_KEY`，2026-09-28 接入）排在所有市场的最后一位。免费档实测（2026-09-28）只覆盖美股 / ETF、外汇、加密货币，每天 800 次、每分钟 8 次；欧股返回"需 Grow / Pro 档"，日股返回无数据。所以**日股、欧股目前实际只有 Yahoo 一个来源**。代码遇到"需升级"会在本次运行内跳过该市场；以后升级付费档无需改代码。期货、指数不走 Twelve Data（它的商品是现货，不是期货合约）。
- **上下文之外的标的**：影子可以交易观察清单以外、但属于自己领域的标的。运行器会补取它的行情，取不到就丢弃这笔决策。因为影子没看到这个标的的价格，它给的止损、目标、证伪价位一律丢弃，只保留文字形式的证伪条件，并在 meta 里标注 `off_context`。
- **观察清单**：各领域加入海外标的（期货、外汇、港股、A 股、日股、欧股等）。
