# S6 设计：实盘持仓录入与巡检

> 规格来源：`docs/SPEC_v3.md` §1、§2（L2）、§7、§10、§13（S6 验收：亏损时输出离场 / 持有 / 换仓分析）。日期：2026-09-28。

## 范围

- **做**：所有人手动录入 Robinhood 持仓；持仓同时写进统一账本（`owner`，"人类决策镜像"）；每日巡检，亏损持仓给出离场 / 持有 / 换仓结论与依据；仪表盘"实盘持仓"页。
- **不做**：Robinhood 加密 API 只读同步（需要所有人申请 API 密钥，记为待办）；期权（实盘不碰期权）；任何下单或券商写操作（L2）；让 LLM 下结论（结论全部由代码规则给出）。

## 隐私

- 持仓存放在 `data/holdings.json`。`data/` 已被 `.gitignore` 忽略，仓库是公开的，**持仓绝不入库**。
- 旧的 `marketmind/input/account_state.json` 在库里，不再使用，也不要往里写真实持仓。

## 录入（命令行）

```
python -m marketmind.holdings list
python -m marketmind.holdings add AAPL 10 180.50 [--opened 2026-09-01] [--stop 170] [--note "..."]
python -m marketmind.holdings remove AAPL
python -m marketmind.holdings inspect
```

- `add`：写入持仓文件，并在账本记一条 `source_type=owner` 的记录：做多、下一个开盘价入场、持有 60 个交易日、仓位 = 数量 × 成本、确信度记为默认值 0.5（`confidence_is_default=True`）、可证伪条件 = 所有人填的止损，没填就写"所有人未设止损"。同一标的再次 `add` 视为加仓，合并成本（加权平均），账本另记一条。
- `remove`：只从持仓文件删除；账本记录保留，按自己的持有期结算。
- 期权代码（含空格或 OCC 格式）拒绝录入。

## 巡检规则（纯代码，`marketmind/holdings/inspect.py`）

对每个持仓：取行情 → L3 快照（`pipeline/l3_indicators.compute_snapshot`）→ 浮动盈亏 = 现价 / 成本 − 1。

| 结论 | 条件（按顺序判断） |
|---|---|
| **离场** | 现价跌破所有人设的止损；或 L3 红灯；或跌破 200 周均线且结构已破坏 |
| **换仓** | 未触发离场，持仓自身 R/R < 1，且存在 R/R ≥ 2、比持仓高至少 1 的替代标的 |
| **持有** | 其他情况 |

- 盈利中的持仓也跑同样的规则，但结论标注"盈利中"。
- **替代标的**：近 5 天账本里主管线和影子做多过、所有人可在 Robinhood 执行的标的，重新算 L3，取 `recommendation = enter`（绿灯且 R/R ≥ 2）中 R/R 最高的 3 个。
- **账本证据**：近 10 天影子对该标的的多空记录数；该标的已结算记录的平均净收益；证据层当天涉及该标的的背离。
- 行情取不到时结论为"数据不可用"，不给建议。

## 输出

- `data/holdings_reports/<日期>.json`；仪表盘 `/api/wb/holdings` 读最新一份（没有持仓时显示"未录入持仓"）。
- 离场、换仓结论同时发一条站内警报（`notification/alert_manager`，仪表盘可见）。
- 每日运行最后一步执行巡检（在影子交卷之后，替代标的能用上当天的影子记录）；也可单独 `inspect`。
- 汇报员能读到最新巡检结果。

## 验收

- 离线测试：录入 / 加仓 / 删除 / 拒绝期权；账本镜像记录；三种结论各自的触发；替代标的筛选；数据缺失。
- 用一个临时持仓文件跑一次真实巡检（真实行情），报告和仪表盘可见；测完删除临时持仓，不留在所有人的持仓文件里。
